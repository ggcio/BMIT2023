3. CORE MODULES (3 MODULES)
--------------------------------------------------------------------------------
MODULE 1: Security (Workload: Heavy)
- Login & Logout: Implement manual cookie-based authentication.
- Registration: Allow new users to register (with an optional Student ID field).
- Password Security: Hash passwords using ASP.NET Core's built-in PasswordHasher.
- Role-Based Access Control (RBAC): Enforce permissions for Super Admin, Admin, and Member roles.
- Access Denied Page: Build a custom access-denied view for unauthorized URL access.

MODULE 2: Admin and Member Maintenance (Workload: Medium)
- Admin Account CRUD (Super Admin ONLY):
  * Create, read, update, and delete Admin accounts.
  * Enforce rule: Only the single seeded Super Admin can access this, and the Super Admin account itself cannot be edited or deleted in the UI.
- Member Account CRUD:
  * View, edit, delete, block, and unblock Member accounts.
- Profile & Student Status Application (Member side):
  * Allow Public members to update their profile and apply for Student status at any time by submitting a Student ID.
  * Data structure: Store Student ID and Status (None, Pending, Approved, Rejected) directly on the Member entity (no extra roles/subclasses/tables).
- Student Application Review (Admin side):
  * Allow Admins to approve or reject pending student applications with a short review note/reason displayed to the member.
  * Approved status grants free bookings for all future reservations.
  * Rejected members must be allowed to re-apply.

MODULE 3: Booking History - Member (Workload: Light)
- Booking List & Details: Display the logged-in member's own booking history and individual booking details (including QR e-ticket/status).
- Booking Cancellation: Implement cancellation logic based on member rules:
  * Students: Can cancel at any time.
  * Public Members: Can cancel up to 24 hours before the slot start time (marks booking as "Refund Due" for Admin processing).
